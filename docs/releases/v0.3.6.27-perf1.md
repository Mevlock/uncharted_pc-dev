**Test build: frame-rate work. Not the normal release.** This is 0.3.6.27 with a rework of how the port hands the game's GPU work to your graphics card. It has been played for a few hours on one PC and run through a few hundred scripted test runs, so expect rough edges. If something goes wrong, use the normal 0.3.6.27 release: your saves and settings work with both.

**Installing:** unpack into a **new folder**, not over your normal install, and start `Uncharted.exe`. This build keeps its own shader cache, so the first start of each game compiles shaders again (some stutter for the first minutes). The window title, the settings menu and a line under the FPS counter say **PERF BUILD**, so you can always tell which one you are running.

## Faster when the processor is the limit
**About +22% when the processor sets the pace, about +4 to +13% at native resolution on a strong graphics card, little or nothing where the graphics card is the limit.** Measured on one PC: your numbers will differ.

| Same build without the perf work → perf build | Uncharted 1 | Uncharted 2 | Uncharted 3 |
|---|---|---|---|
| DLSS Performance (1712 × 704 → 3440 × 1440) | 159 → 194 FPS (+22%) | 178 → 218 FPS (+23%) | 115 → 140 FPS (+22%) |
| Native 3440 × 1440 | 133 → 138 FPS (+4%) | 125 → 138 FPS (+10%) | 116 → 131 FPS (+13%) |
| Older 4-core CPU (simulated: 8 threads at 60% clock), DLSS Performance | | | 62 → 77 FPS (+24%) |
| Same, Uncharted 3's heaviest crowd scene (rooftop chase) | | | 81 → 89 FPS (+10%) |

How it was measured: RTX 5080 with a 16-thread CPU, Windows 11, EU versions, DLSS, frame generation off, frame rate uncapped, the same saved spot each run (U1 jungle, U2 an early chapter, U3 Cartagena street), 2 minutes per run, the two builds taking turns over 2 rounds; the rounds agreed within about 2% (Uncharted 1 at native within 7%).

- **Steadier frame times, not only more frames.** Uncharted 3 at 1920 × 1080, uncapped: the slowest 1% of frames took 9.3 ms instead of 12.6 ms, and no frame took more than 1.5 times the usual frame time (12 in the same 2 minutes without the perf work). The port's three threads (see below) now wait for each other far less often: fence hand-offs go in batches, the constant data has a thread of its own, and end-of-shader markers no longer make the draw recorder empty its queue first. A heavy frame is absorbed by the slack instead of showing as a hitch.
- **Where you will see it:** DLSS or FSR upscaling (Quality, Balanced, Performance), high frame rates, older or slower processors. Drawing a smaller picture leaves the processor as the limit, and that is the part this build speeds up.
- **Where you will not:** native resolution on a wide or 4K screen with a mid-range graphics card, or a frame rate cap your PC already holds: there the graphics card or the cap sets the pace. You may still get steadier frame times.
- The "older CPU" rows simulate a 4-core processor on a fast one. Real older processors also pay more for the operating system's security fixes, so their results can be lower.

## What changed under the hood
The PS4 version of each game sends its GPU a stream of commands: draw this, run that compute job, wait for this, copy that. The port has to turn every one of those into Vulkan commands your graphics card understands, and in a busy scene that is tens of thousands of commands a second. When the CPU is the limit, this translation is most of the work.

Since 0.3.6.20 the translation already runs as a production line of three threads working on the same frame side by side:
  - the **command processor** reads the game's command stream and works out what each command needs;
  - the **draw recorder** prepares each draw: which buffers, textures and shaders it uses, and what has to finish on the GPU before it may run;
  - the **Vulkan recorder** writes the finished Vulkan commands and hands them to the graphics card.

At high frame rates the command processor and the draw recorder were each busy for nearly the whole frame, so this build takes work off both of them and cuts the waiting between the three:

- **The game's constant data is copied by a thread of its own.** Every draw reads small blocks of values from the game's memory (positions, colours, light settings), which are copied into a ring the GPU reads from. Finding room in the ring, checking whether the GPU changed the data and making the copies now happen on a separate thread, in order, while the draw is still on its way through the stages, instead of on the command processor. The draw recorder only has to point the draw at its copy.
- **Less work per draw.** Neighbouring read-only buffers of a draw are bound together instead of one by one; buffers that hold only this frame's copies skip the tracking that decides what the GPU must wait for (nothing the GPU wrote can be in them); and each buffer description is read once per draw instead of several times.
- **Fewer hand-offs between the threads.** The game sets a fence after almost every compute job (about 1,900 a frame in Uncharted 3); each one used to force the draw recorder to hand its work to the Vulkan recorder at once. They are now handed over in batches (up to 16, or as soon as the draw recorder runs out of work). Mid-frame flushes keep their order on the draw recorder, so no thread has to wait for another to catch up.
- **Less waiting between the stages** (by che2281337): the end-of-shader markers the game sets are attached to work already queued for the GPU, so they no longer hold up the draw recorder; and a display wait that is already met no longer stops to empty the draw queue first.
- **Uncharted 2:** a depth buffer the game rebuilds twice every frame reuses its memory instead of being made again each time (by che2281337).

The result: each frame gets through the three stages sooner. Your graphics card still sits idle for part of every frame at high frame rates, waiting for the CPU side; letting it start on a frame earlier is the next big step, and not in this build.

## Known limits
- Measured on one PC. Older 4-core processors are simulated, not tested on real hardware.
- Played mostly in Uncharted 3, with scripted runs in all three games.
- Not tested yet on AMD graphics cards, integrated graphics, Linux or the Steam Deck.
