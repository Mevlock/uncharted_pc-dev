**Pre-release: needs testing.** This build is much faster, but its changes go deep into how the port handles the GPU and have only been played for a short time: the Cartagena square and a street there, Uncharted 3's chapter 1 (the pub and the bar fight, with Alt-Tab), and short stretches of Uncharted 1 and 2. If something goes wrong (a crash, a freeze, glitching characters or objects), go back to 0.3.6.16, the last build without these changes.

**Unofficial fork build.** The official port is [SuperMedo's uncharted_pc](https://github.com/Supermedo/uncharted_pc); please don't report problems with this build to him. This is SuperMedo's 0.3.6 plus this fork's changes; everything in 0.3.6.16 plus the list below.

**Installing:** unpack into a new folder and start `Uncharted.exe`. Your launcher settings carry over, but saves live in each install's own `user\savedata` folder: copy that folder over from your previous install, or set **Saves folder** in the launcher to it.

## New in 0.3.6.21 (pre-release)
- **Uncharted 2: fixed freezes on death and when a cutscene switched to a video** in the recent pre-releases. Two of the port's own threads could end up waiting for each other. Found with logs from HotZin.
- **Uncharted 2: fixed the frame rate dropping to about 12 FPS in chapter 9** after entering the temple room, until the game was reloaded (this one also happened in 0.3.6.16). The port gave a shadow map 16 times its real size; the game kept other data in that memory, and each time it changed some, the port re-checked the whole 1 GB. Shadow maps now keep their real size, and checks after the game's writes only look at what was written. Found with logs and a save from M4asterC.
- **Fewer slowdowns on Intel CPUs with performance and efficiency cores** (12th generation and later): the port's render threads stay on the performance cores, and Windows' efficiency mode no longer applies to the game.
- **A crash seen in testing with only 4 CPU cores is avoided:** one of 0.3.6.20's speed-ups (waits on GPU results that are queued but not yet written) is off until its cause is found. No measurable FPS change on our PC.
- More detail in logs for diagnosing slowdowns (`BB_FRAME_STATS=1`, `BB_SAMPLE_THREADS=1`).

## From 0.3.6.20 (pre-release)
- **No more freezes when closing the game.** Closing the window could leave the game hanging in Task Manager; it now always ends.
- **A damaged shader cache repairs itself.** The cache keeps each shader as two files; if they ever come from different versions (after a crash, or when Windows refuses to replace a file in use), the pair is now thrown away and rebuilt, instead of a surface being drawn with the wrong shader (after an idea from BilalReloaded's port).
- **Uncharted 2: lighting with many lamps fixed.** The tiled lighting shader only saw about the first four lights; the rest lit every pixel, so lamp-heavy scenes were too bright and slow. By Umar-Qayyum-dev.
- **Uncharted 3: auto exposure on NVIDIA fixed.** Part of the scene-brightness measurement was lost on NVIDIA cards, so scenes measured too dark and were brightened too much (white ledges, washed-out walls, brightness jumping while walking). By Umar-Qayyum-dev.
- **Uncharted 2: depth of field while aiming** reads the focus distance the GPU computes in more cases.
- **Fewer crashes from interrupted functions:** protection for game code that keeps data just below the stack, which Windows could overwrite while the port handled memory faults. By Umar-Qayyum-dev.
- **A little faster:** small read-only data copied once per command buffer instead of once per use, fewer pointless waits between the GPU threads, and less CPU spinning while threads wait (helps 4-core CPUs most). By Umar-Qayyum-dev. About +3 FPS in Uncharted 3's Cartagena square on our PC.
- When a freeze makes the port wait for GPU work that never comes, the log now also lists every thread and where it waits.

The shader cache is rebuilt once on the first start of each game (some stutter early on).

## From 0.3.6.19 (pre-release)
- **More robust GPU write handling** (follow-up to the 0.3.6.18 museum-crash fix). When the game and the GPU both change data close together, the GPU's result now only goes in where the game hasn't changed that data in the meantime, so neither side's data can be overwritten with the other's.
- Memory the GPU writes again straight after its earlier result arrived is no longer treated as changed by the game, which avoids needless re-uploads.
- The check that skips textures pointing outside memory now looks at the right page.
- The **precise read-backs** setting (`BB_READBACKS=2`) no longer freezes the game at launch. It's a diagnosis setting; normal play doesn't use it.

## From 0.3.6.18 (pre-release)
- **Uncharted 3: fixed a crash in chapter 2 when leaving the museum** (0.3.6.17-pre only). When the game rewrote data next to data the GPU was still writing, the two could get mixed inside a single value, which left texture addresses pointing at memory that doesn't exist. They no longer mix, and a texture that doesn't fit in memory is now skipped instead of crashing the game.
- The launcher's **Log** page starts with the build's version, as `last_run.log` does, so copied logs say which build they came from.

## From 0.3.6.17 (pre-release)
**Significantly higher frame rates**, most in busy scenes. Measured on one PC (NVIDIA RTX, 3440 × 1440, no frame cap):

| Scene | 0.3.6.16 | 0.3.6.17 |
|---|---|---|
| Uncharted 3, Cartagena square | ~87 FPS | ~120 FPS |
| Uncharted 3, busiest street view in Cartagena | 74 FPS | 124 FPS |
| Uncharted 3, chapter 1 pub | 100–126 FPS | 134–144 FPS (144 Hz limit) |
| Uncharted 2, museum | ~117 FPS (120 limit) | ~125 FPS |
| Uncharted 1, jungle | ~114 FPS | ~120 FPS |

What changed:
- **The game no longer waits for the GPU when it writes next to data the GPU is still working on.** That happened about 50 times a second in Uncharted 3, a few milliseconds each time; the write now goes ahead at once and the GPU's data follows as soon as it's ready (after an idea from BilalReloaded's port).
- **Less work per draw** on the thread that records the GPU's commands: the check for which memory needs a barrier was a deep search on every buffer binding (about a fifth of that thread's time) and is now a quick lookup with the same answers.
- **The two GPU threads wait for each other less:** write faults and the game's small copy jobs now run in order with the draws instead of stopping the command thread each time.

If one of these changes causes a problem, it can be switched off on its own with an entry in **Environment** on the launcher's **Advanced** page:
- `BB_SHARED_WRITES=0`: writes next to GPU data wait for the GPU again.
- `BB_ORDERED_FAULTS=0`: write faults are handled on the command thread again.
- `BB_PIPELINED_COPY_HLE=0`: the small copy jobs run on the command thread again.
- `BB_BARRIER_TRACKER=tree`: the old barrier check.

## Known issues
- This is a pre-release: see the note at the top.
- Native 4K (the two experimental Render resolution choices) has had only short tests; if a game crashes or looks wrong with one, go back to Native.
- Uncharted 3: single-frame lighting flashes are rarer since 0.3.6.7 but may not be gone entirely.
- Uncharted 1 and 2 with Quality, Balanced or Performance, and Uncharted 2 at native resolution, work in the opening areas but haven't had a full playthrough (cutscene videos, HUD, menus).
- Ultrawide: short scripted scenes can still switch to 16:9 by mistake; **Always fill** avoids it.
- Fast mouse aiming covers the EU (CUSA02343), US (CUSA02320) and EU/Russian (CUSA02344) versions; other versions keep stick-style aiming.
- DLSS Frame Generation goes up to 4×.
