**Test build: frame-rate work, second round. Not the normal release.** This is 0.3.6.29 with the perf build's rework of how the port hands the game's GPU work to your graphics card, plus a second round of that work. It has been played on one PC and run through a few hundred scripted test runs, so expect rough edges. If something goes wrong, use the normal 0.3.6.29 release: your saves and settings work with both.

**Installing:** unpack into a **new folder**, not over your normal install, and start `Uncharted.exe`. This build keeps its own shader cache, so the first start of each game compiles shaders again (some stutter for the first minutes). The window title, the settings menu and a line under the FPS counter say **PERF BUILD**, so you can always tell which one you are running.

## Faster again when the processor is the limit
**On top of the first perf build: about +6% in Uncharted 2 and 3, about +13% on a slower processor, about +2% in Uncharted 1** (where the processor sets the pace). Little or nothing where the graphics card is the limit. Measured on one PC: your numbers will differ.

| First perf build → perf2 (DLSS Performance, 3440 × 1440 output) | FPS |
|---|---|
| Uncharted 3, Cartagena square | 146 → 156 (+7%) |
| Uncharted 3, older 4-core CPU simulated (8 threads at 60% clock) | 77 → 87 (+13%) |
| Uncharted 2, museum | 150 → 159 (+6%) |
| Uncharted 1, jungle | 202 → 206 (about +2%, within the noise of this spot) |

How it was measured: RTX 5080 with a 16-thread CPU, Windows 11, EU versions, DLSS Performance, frame generation off, frame rate uncapped, the same saved spot each run, 2 runs per build. The final build was checked again against these numbers on the day of release (U3 156, U2 159, U1 207 FPS). The first perf build's own gains (about +22% where the processor is the limit) are in its release notes and still apply.

- **Where you will see it:** DLSS or FSR upscaling, high frame rates, busy scenes with thousands of objects, older or slower processors.
- **Where you will not:** native resolution with a graphics card that is already fully busy, or a frame rate cap your PC already holds.
- The "older CPU" row simulates a 4-core processor on a fast one; real older processors can do worse.

## What changed under the hood
The port's translation of the game's GPU commands runs as three threads (command processor, draw recorder, Vulkan recorder). After the first perf build, the command processor and the draw recorder were both close to fully busy. This round takes more work off both:

- **The draw recorder no longer waits for the Vulkan recorder** before each plain submission: the Vulkan recorder submits the finished work itself as its last step, and the draw recorder carries on with the next frame's draws.
- **Faster tracking of memory the GPU is about to write:** a list kept in order with a quick 64 KB filter, instead of a search per draw.
- **One lock per check of a shader's resource tables** instead of one per entry.
- **Game writes to memory the GPU also uses are read back on the thread that wrote, straight away** (che2281337's idea), instead of waiting for the command processor. A crash this caused in testing (older GPU data stored over pages the game had already read back) is fixed: those copies now skip pages that are no longer GPU data, and the writing thread backs off while the GPU copies data back.

## Also in this build: everything in 0.3.6.29
- **Uncharted 1 and 2: no more stop on `pAction != NULL`** at high frame rates.
- **Video memory give-back (4 to 6 GB cards): safer.** Memory is unmapped only after the graphics card has finished with it, is watched before it is handed back, and a range used again straight away keeps its own memory.

See the 0.3.6.29 release notes.

## For developers
How each part works, the measurements, the switches and what was tried and dropped: `docs/PERF_BUILD.md` in this branch. Every change has an off switch (for example `BB_ASYNC_SUBMIT=0`, `BB_PENDING_FAST=0`, `BB_FAULT_HERE=0`).

## Known limits
- Measured on one PC. Older processors are simulated, not tested on real hardware.
- Not tested yet on AMD graphics cards, integrated graphics, Linux or the Steam Deck.
