**Pre-release: needs testing.** New to try in this one: the 1:1 mouse aiming in all three games, mirrors and water on ultrawide screens, and Uncharted 3's bloom. It was tested in short sessions of all three games on the EU and US versions.

**Frame rate on 4-core CPUs:** one player with a 4-core / 8-thread CPU (i7-7700K) sees a lower frame rate since 0.3.6.20 than with 0.3.6.17 to 0.3.6.19. We're looking into which change causes it. If your CPU has 8 threads or fewer and this build is slower for you than 0.3.6.19, 0.3.6.19 remains a good fallback; reports with your CPU, game and scene help.

**Unofficial fork build.** The official port is [SuperMedo's uncharted_pc](https://github.com/Supermedo/uncharted_pc); please don't report problems with this build to him. This is SuperMedo's 0.3.6 plus this fork's changes; everything in 0.3.6.16 plus the list below.

**Installing:** unpack into a new folder and start `Uncharted.exe`. Your launcher settings carry over, but saves live in each install's own `user\savedata` folder: copy that folder over from your previous install, or set **Saves folder** in the launcher to it.

## New in 0.3.6.25 (pre-release)
- **New mouse aiming in all three games: true 1:1.** The mouse now turns the game's own aim direction instead of acting as a fast right stick, so aiming turns exactly as far as looking around does, at any frame rate, with the game's aim assist and recoil still working. Rolling straight into aim points where you look, and the mouse now also works in cover. EU, US and EU/Russian versions. By Umar-Qayyum-dev (ported to the EU version here).
- **Uncharted 3: fixed round red and blue spots in the bloom** (soft blotches floating over the picture, mostly in darker areas, in many chapters). The bloom is drawn in several steps of decreasing size; when another image shared the same memory, two of those steps were drawn into the wrong place and kept showing an old frame. Depending on the render size and the graphics card it showed on some PCs and not others. Reported by adelhmv-glitch; fix after zorde23's.
- **Native 4K: cutscene videos no longer show zoomed in** (3840 × 2160 render resolution, all three games; only part of the video was visible). Reported by adelhmv-glitch.
- **Ultrawide: mirrors and water look right at the sides of the screen.** Reflections were drawn for a 16:9 picture, so in the wider part of the screen they showed stretched bands (Uncharted 3's pub bathroom mirror) or water shimmering differently than in the middle. The torch fix from 0.3.6.15 is kept.
- **Unlock all chapters** (launcher, Console page): every chapter in Chapter Select and the Brutal difficulty from the start, in all three games and in the EU, US and EU/Russian versions. Saves and progress are not changed; turned off, the menus show your own progress again. By BilalReloaded.
- **US and EU/Russian versions: the 4-core crash fix from 0.3.6.23 now applies to them too** (Uncharted 2 crashing on CPUs with 4 cores, the log ending with `cmdBuf.m_bInUse == false` or `m_workerThreadIndex == GetCurrentWorkerThreadIndex()`). These versions build that part of the game differently, so the fix had not been applied there.
- **Smoother camera turning in all three games** (mouse and controller). The game's job threads, which run the camera and controls, used to sleep whenever they had nothing to do; waking them took a varying amount of time, so a steady turn came out uneven on screen (about every fourth frame turned only a third as far). On CPUs with more than 8 threads they now keep running between jobs, as on the PS4. This uses several CPU cores and costs a few percent of frame rate (Uncharted 3, Cartagena square: about 120 to 115-117 FPS on our PC). On CPUs with 8 threads or fewer they still sleep, to leave the cores to the rest of the game. **Display → Idle game threads** chooses: Automatic, Spin (smoothest) or Sleep (saves CPU).
- **Sleeping job threads no longer miss work.** A job submitted just as a thread fell asleep woke nobody, and that frame's work came a frame late (Uncharted 3's one-frame lighting flashes, until now avoided by spinning much longer before sleeping). The wake-up is no longer lost, so sleeping threads use less CPU. `BB_JOB_STICKY=0` in **Environment** brings back the previous behaviour.
- **EU version (CUSA02343): idle job threads now hand the CPU to other work**, as the US versions already did (helps CPUs with 8 threads or fewer, where they sleep instead of spinning).
- **Uncharted 1: steadier mouse turning** of the walking camera: the mouse's movement is spread evenly over the frames instead of arriving in uneven chunks.
- Shader translation fixes from shadPS4 (branching code and shared-memory barriers), and texture-cache fixes for images whose data the game rewrites. The shader cache is rebuilt once on the first start of each game (some stutter early on).
- **The launcher keeps the last five run logs** (`last_run.log`, then `last_run.1.log` to `last_run.4.log`), so restarting after a problem no longer overwrites the log that shows it.

## From 0.3.6.24 (pre-release)
- **US and EU/Russian versions (CUSA02320, CUSA02344): fixed Uncharted 2 and 3 crashing seconds after a save loads** (0.3.6.20 to 0.3.6.23) on ultrawide screens, with a field of view other than 100%, or with a render size wider than 16:9. One of the ultrawide patch's checks was written as a broken instruction when the game kept its camera in a particular register, which only these versions do. The EU/UK version (CUSA02343) and 16:9 play were not affected.
- **Older Intel CPUs: the games now run on Sandy Bridge and Ivy Bridge** (2nd and 3rd generation Core, about 2011 to 2013), which lack some instructions the games use. On those CPUs the port finds the places that use them on first start and runs a replacement instead. Newer CPUs are unaffected. By drakolordx7, based on FelipePrado0's SpartanPort.
- **CPUs with 8 threads or fewer: the thread priorities from 0.3.6.23 are removed again.** The 4-core crash they were meant to help with had another cause (fixed in 0.3.6.23), and a 4-core test ran slightly faster without them (31.1 against 29.5 FPS). `BB_THREAD_PRIO` no longer does anything.
- When the game crashes, the log now also shows the code at the crash and the code addresses on the stack.

## From 0.3.6.23 (pre-release)
- **Uncharted 2: fixed a crash on PCs with 4 CPU cores** (the log ends with `cmdBuf.m_bInUse == false` or `m_workerThreadIndex == GetCurrentWorkerThreadIndex()`). In testing it came within a few deaths and reloads. While drawing water the game waits for other jobs, and on a busy 4-core CPU they were not done yet, so the job went to sleep and woke up on another thread with that thread's drawing unfinished. A job that is drawing now waits in place.
- **Uncharted 2 and 3 start from the collection's own game menu** (with `BB_SKIP_COLLECTION_MENU=0`): they showed a white screen. The game they start now also gets the focus, so the controller works without clicking the window first. Reported by linkmendez.
- **CPUs with 8 threads or fewer:** the game's threads get the priorities they have on the PS4, so its own job threads no longer crowd out the threads that load and stream. By drakolordx7. On CPUs with more threads nothing changes; `BB_THREAD_PRIO=1` or `0` in **Environment** forces it on or off.
- **Uncharted 2: fixed a rare stop in the museum** ("GPU library assertion failed"): a shader read a damaged buffer description with a format the port can't translate; it now reads zeros, like an empty buffer.
- **Uncharted 1, 2 and 3: fewer crashes from damaged game data:**
  - A missing shader input handler is skipped instead of called (a crash in Uncharted 1's jungle chapters). By soni424 and drakolordx7.
  - A draw whose pipeline the graphics driver can't create is skipped instead of stopping the game ("Failed to create graphics pipeline", seen at start on an AMD card). By SuperMedo.
  - A draw without vertex data is skipped. By SuperMedo.
  - Damaged GPU commands skip the rest of their batch instead of stopping the game. By SuperMedo and parsifal295.
- **Texture memory is freed more reliably:** textures that can't be freed no longer block the rest, and textures unused for 20 seconds are let go. By parsifal295 and iannitram.
- **Graphics cards without sparse memory support on the graphics queue** use another queue for it, and large texture conversions are split for cards with lower limits. By Hugo Borges.
- The log now names the graphics card, its video memory and the driver version.

## From 0.3.6.22 (pre-release)
- **Possible fix for random crashes and freezes on some PCs.** The protection added in 0.3.6.20 for game code that keeps data just below the stack needs memory close to the game's code. On some PCs the graphics driver had already taken that memory when the protection was set up, so most of it was never applied (the log said "left as they were" with a large number). It now reserves that memory before the graphics driver starts. Found with logs from M4asterC.
- When the game shows no new frame for 20 seconds (a freeze), the log now lists every thread and where it waits, so freezes can be tracked down from one log.

## From 0.3.6.21 (pre-release)
- **Uncharted 2: fixed freezes on death and when a cutscene switched to a video** in the recent pre-releases. Two of the port's own threads could end up waiting for each other. Found with logs from HotZin.
- **Uncharted 2: fixed the frame rate dropping to about 12 FPS in chapter 9** after entering the temple room, until the game was reloaded (this one also happened in 0.3.6.16). The port gave a shadow map 16 times its real size; the game kept other data in that memory, and each time it changed some, the port re-checked the whole 1 GB. Shadow maps now keep their real size, and checks after the game's writes only look at what was written. Found with logs and a save from M4asterC.
- **Fewer slowdowns on Intel CPUs with performance and efficiency cores** (12th generation and later): the port's render threads stay on the performance cores, and Windows' efficiency mode no longer applies to the game.
- **A crash seen in testing with only 4 CPU cores is avoided:** one of 0.3.6.20's speed-ups (waits on GPU results that are queued but not yet written) is off until its cause is found. No measurable FPS change on our PC.
- More detail in logs for diagnosing slowdowns (`BB_FRAME_STATS=1`, `BB_SAMPLE_THREADS=1`).

## From 0.3.6.20 (pre-release)
- **No more freezes when closing the game.** Closing the window could leave the game hanging in Task Manager; it now always ends.
- **A damaged shader cache repairs itself.** The cache keeps each shader as two files; if they ever come from different versions (after a crash, or when Windows refuses to replace a file in use), the pair is now thrown away and rebuilt, instead of a surface being drawn with the wrong shader (after an idea from BilalReloaded's port).
- **Uncharted 2: lighting with many lamps fixed.** The tiled lighting shader only saw about the first four lights; the rest lit every pixel, so lamp-heavy scenes were too bright and slow. By Umar-Qayyum-dev.
- **Uncharted 3: auto exposure on NVIDIA fixed.** Part of the scene-brightness measurement was lost on NVIDIA cards, so scenes measured too dark and were brightened too much (white ledges, washed-out walls, brightness jumping while walking). By Umar-Qayyum-dev.
- **Uncharted 2: depth of field while aiming** reads the focus distance the GPU computes in more cases.
- **Fewer crashes from interrupted functions:** protection for game code that keeps data just below the stack, which Windows could overwrite while the port handled memory faults. By Umar-Qayyum-dev.
- **A little faster:** small read-only data copied once per command buffer instead of once per use, fewer pointless waits between the GPU threads, and less CPU spinning while threads wait (helps 4-core CPUs most). By Umar-Qayyum-dev. About +3 FPS in Uncharted 3's Cartagena square on our PC.
- When a freeze makes the port wait for GPU work that never comes, the log now also lists every thread and where it waits.

The shader cache is rebuilt once on the first start of each game (some stutter early on).

## From 0.3.6.19 (pre-release)
- **More robust GPU write handling** (follow-up to the 0.3.6.18 museum-crash fix). When the game and the GPU both change data close together, the GPU's result now only goes in where the game hasn't changed that data in the meantime, so neither side's data can be overwritten with the other's.
- Memory the GPU writes again straight after its earlier result arrived is no longer treated as changed by the game, which avoids needless re-uploads.
- The check that skips textures pointing outside memory now looks at the right page.
- The **precise read-backs** setting (`BB_READBACKS=2`) no longer freezes the game at launch. It's a diagnosis setting; normal play doesn't use it.

## From 0.3.6.18 (pre-release)
- **Uncharted 3: fixed a crash in chapter 2 when leaving the museum** (0.3.6.17-pre only). When the game rewrote data next to data the GPU was still writing, the two could get mixed inside a single value, which left texture addresses pointing at memory that doesn't exist. They no longer mix, and a texture that doesn't fit in memory is now skipped instead of crashing the game.
- The launcher's **Log** page starts with the build's version, as `last_run.log` does, so copied logs say which build they came from.

## From 0.3.6.17 (pre-release)
**Significantly higher frame rates**, most in busy scenes. Measured on one PC (NVIDIA RTX, 3440 × 1440, no frame cap):

| Scene | 0.3.6.16 | 0.3.6.17 |
|---|---|---|
| Uncharted 3, Cartagena square | ~87 FPS | ~120 FPS |
| Uncharted 3, busiest street view in Cartagena | 74 FPS | 124 FPS |
| Uncharted 3, chapter 1 pub | 100–126 FPS | 134–144 FPS (144 Hz limit) |
| Uncharted 2, museum | ~117 FPS (120 limit) | ~125 FPS |
| Uncharted 1, jungle | ~114 FPS | ~120 FPS |

What changed:
- **The game no longer waits for the GPU when it writes next to data the GPU is still working on.** That happened about 50 times a second in Uncharted 3, a few milliseconds each time; the write now goes ahead at once and the GPU's data follows as soon as it's ready (after an idea from BilalReloaded's port).
- **Less work per draw** on the thread that records the GPU's commands: the check for which memory needs a barrier was a deep search on every buffer binding (about a fifth of that thread's time) and is now a quick lookup with the same answers.
- **The two GPU threads wait for each other less:** write faults and the game's small copy jobs now run in order with the draws instead of stopping the command thread each time.

If one of these changes causes a problem, it can be switched off on its own with an entry in **Environment** on the launcher's **Advanced** page:
- `BB_SHARED_WRITES=0`: writes next to GPU data wait for the GPU again.
- `BB_ORDERED_FAULTS=0`: write faults are handled on the command thread again.
- `BB_PIPELINED_COPY_HLE=0`: the small copy jobs run on the command thread again.
- `BB_BARRIER_TRACKER=tree`: the old barrier check.

## Known issues
- This is a pre-release: see the note at the top.
- Native 4K (the two experimental Render resolution choices) has had only short tests; if a game crashes or looks wrong with one, go back to Native.
- Uncharted 3: single-frame lighting flashes are rarer since 0.3.6.7 but may not be gone entirely.
- Uncharted 1 and 2 with Quality, Balanced or Performance, and Uncharted 2 at native resolution, work in the opening areas but haven't had a full playthrough (cutscene videos, HUD, menus).
- Ultrawide: short scripted scenes can still switch to 16:9 by mistake; **Always fill** avoids it.
- Fast mouse aiming covers the EU (CUSA02343), US (CUSA02320) and EU/Russian (CUSA02344) versions; other versions keep stick-style aiming.
- DLSS Frame Generation goes up to 4×.
